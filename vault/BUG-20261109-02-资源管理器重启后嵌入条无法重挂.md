# BUG-20261109-02 修复：资源管理器重启后任务栏嵌入条无法重挂

## 需要先读
- 项目备忘录.md
- docs/开发进度.md
- vault/14-位置外观增强需求包.md（T5 验收项「重启 Explorer 后自动重挂」）
- vault/BUG-20261109-01-任务栏嵌入条点击异常.md（第 2 轮首次在日志中发现本问题）
- src-tauri/src/taskbar.rs（`ensure_strip_window` / `enter` / `leave`）、src-tauri/src/monitor.rs（运行时巡检）

## Bug 摘要与根因假设
- 实际表现：任务栏模式下资源管理器重启后，嵌入条消失且不再出现；日志每 2 秒报一次「嵌入任务栏失败：无效的窗口句柄。(0x80070578)」，直到重启 LuckyIsland。
- 期望表现：资源管理器重启后数秒内嵌入条自动回到任务栏，点击照常可用（模块 14 T5 验收项）。
- 复现路径：任务栏模式下结束并重启 explorer.exe。
- 影响范围：只影响 taskbar 模式。
- 根因（复现与 Tauri 2.11.5 / tauri-runtime-wry 2.11.4 源码确认）：
  1. 嵌入条是 `Shell_TrayWnd` 的子窗口，资源管理器退出时被系统连带销毁，但我们的窗口过程收不到 `WM_DESTROY`，Tauri 不会触发 `Destroyed`，窗口对象和标签 `taskbar-strip` 一直留在管理器里，`hwnd()` 返回失效句柄。
  2. 重挂流程拿失效句柄去 `SetParent`，每次都失败；`leave` 恢复父窗口失败时提前返回、不清理状态。
  3. `WebviewWindow::destroy()` 只把 wry 内部窗口指针置空，标签要等 `Destroyed` 事件才注销，因此不能用同名标签重建。

## 选定方案
- 用户 2026-11-09 选择「重建嵌入条再挂回」，并授权由主 Agent 重启资源管理器复现与验证（12:27/12:29 两次资源管理器重启经用户确认是手动重启，不是嵌入条导致崩溃）。
- 改动：
  - `taskbar.rs`：`strip_label(generation)` 生成标签（首个沿用 `taskbar-strip`，重建为 `taskbar-strip-r<n>`）；`strip_window` 按当前代数取窗口；`ensure_strip_window` 在嵌入条未注册或原生窗口已被销毁时按 tauri.conf.json 的配置换新标签重建。
  - 重建只在运行时巡检（tokio 后台任务）里做：新建 WebView 会等待主线程，在主线程的 WebView IPC 回调里新建 WebView2 会死锁，而 `run_on_main_thread` 在主线程上是同步执行的，无法推迟。
  - `enter` 遇到失效嵌入条直接返回「任务栏嵌入条窗口已失效，正在重建，请稍后再试」，不就地重建（它可能运行在切换界面模式的 IPC 回调里）。
  - `leave` 改为按嵌入时记录的句柄恢复，句柄已失效就跳过恢复、只清理状态。
  - `monitor.rs` 运行时巡检每轮先调用 `ensure_strip_window`（任何界面模式都检查，覆盖重启后到重挂前切换模式的空档）；任务栏模式下随后照常走主线程重挂，点击钩子随 `enter` 重新安装。
  - `capabilities/taskbar-strip.json` 的 `windows` 增加 `taskbar-strip-*`，重建的嵌入条仍能调用后端命令。
- 风险点：失效的旧窗口对象（含其 WebView2 控件）留在 Tauri 中不再使用，每次资源管理器重启泄漏一份；重挂瞬间 wry 会打印一次 `WebView2 error 0x8007139F`（判断来自旧控件，新嵌入条正常）。
