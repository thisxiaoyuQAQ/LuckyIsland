## 各任务规划

### T1 长度自定义（任务 4）

- **KV**：`window:width:<mode>`（横向逻辑像素，整数；缺键回退当前默认 `COMPACT_WIDTH_LOGICAL=720`）。与透明度/偏移同套 `mode_key` 按模式独立；命中 `is_portable_setting` 的 `window:` 前缀随导入导出。
- **后端**：`geometry_for(state)` 当前返回常量宽度；改为「宽度来自 KV 参数」——`current_geometry`/`expanded_physical_height` 等读取 `window:width:<mode>`（经 `current_ui_mode`）。compact/expanded 宽=该值，capsule 恒 240。`resize_window` 已有「保 y、按中心重锚 x」逻辑，宽度变化时自动从中间向两侧伸缩，无需新增定位代码。
- **clamp**：宽度变化后 `clamp_offsets` 用实际窗口物理宽，已按参传入，天然兼容。
- **前端**：`App.tsx` 的 `containerWidthPx` 与 `max-w-[700px]` 由 `ISLAND_STRIP_WIDTH_PX` 常量改为读取宽度（新增模块级 store，仿 `ui-mode.ts`），紧凑/展开内容区宽度跟随；胶囊仍 `CAPSULE_WIDTH_PX=240`。
- **设置**：`AppearancePanel` 加「岛长度」滑块（逻辑像素，范围与默认值在 T1 内定稿并回写本节）；实时预览（仿偏移的节流 + 请求序号）。
- **边界**：宽度只影响横向；展开高度 400、条高 80 不变；最小宽度需保证紧凑态内容（时钟+页签/组件条）不溢出，下限在实现时按内容实测确定。

**🔧 T1 真机反馈修复（2026-08-05，纯前端，自动化全绿 440，待真机复验）。** 两处由你真机发现：
1. **「改长度后岛不实时变，要有别的操作才变」**：根因是 CSS `width` 过渡恒为展开时长 ~360ms，且原生 `resize_window` 的真实窗口宽也在逐帧逼近——紧凑态下拖滑块，前端容器先拉宽而 OS 窗口仍窄，内容被物理窗口裁掉，看起来像「长度没变 + 内容更挤」。修复：`App.tsx` 新增 `islandWidthRef`（渲染期同步），把它与 `containerWidthPx` 一并传给 `IslandTopBar`。
2. **「长度太短后展开页很丑」**：根因是展开页签栏在窄容器里硬挤单行溢出。修复：`window-policy.ts` 新增纯函数 `expandedTabsWrap`（页签约 90px/个 + 200px 余量，超宽则换行）+ `shouldWrapExpandedTabs`；`IslandTopBar` 在 `expanded` 且过窄时把页签栏 `flex-wrap` 换行、顶部条该相位改 `flex-col` 两行布局。判定取 `min(containerWidthPx, islandWidthRef.current)`，保证拖动滑块过程中也按实际容器宽及时换行/回行。
- 新增用例：`expandedTabsWrap`（窄容器多页签换行/加宽或减页不换行/无页签不换行）；`App.layout.test.ts` 顶部条断言改适配条件 class（h-14 保留）。前端 vitest 438→440。

**🔧 T1 真机反馈修复 2（2026-08-05，纯前端，自动化 440 全绿，待真机复验）。** 「长度拉到较短 → 展开一次 → 再拉长，岛长度不实时改」。根因：motion `animate.width` 在**从 240 起播的展开动画**（fps 受限）期间会把 width 钉在动画值上，此时拖滑块的新目标被滞留动画压住（要从 240 追到 1200 需数秒），看似不实时。修复：`App.tsx` 给容器 motion.div 加 `key={`island-w${widthBucket}`}`（`widthBucket = round(containerWidthPx/20)`）——拖滑块改宽度档位即强制重挂载、清掉滞留动画，宽度立即对准新目标；展开/收起本身不改档位，胶囊↔条状↔展开过渡动画不受影响。

**🔧 T1 真机反馈修复 3（2026-08-05，Rust 定位，verify 全绿 440/149，待真机复验）。** 真机观察「从短拉到长，没超过原始大小（720）可正常拉；一旦超过 720 就卡在 720，要别的操作才变」。这一定位推翻了修复 2 的 motion 猜测（已撤销 key-remount 与临时诊断日志）。真根因在 **Rust 定位**：宽度 ≤ 屏内可居中范围时横向 clamp 区间为负、`clamp_offsets` 把窗口压回居中，拖动正常；**加宽超过 720 后**横向 clamp 区间变正、旧 `offset_x` 落进合法区被原样保留，`top_center_position` 把窗口往右推了 offset_x，而 `window_width_set` 当时的 `reapply` 只 `set_size` 不 `set_position`——加宽的窗口左侧顶在原中心线上，**超出部分被屏幕右缘裁掉**，可视宽度停在 720，要别的触发 set_position 的操作才跳正。修复：`window_width_set` 在 `reapply` 后补一次 `restore_island_monitor`（按新宽度 clamp 偏移 + `set_position` 居中 + 落盘 clamp 后偏移，失败仅 warn 不影响宽度落盘），保证超宽也实时贴屏内居中。

### T3 Alt+拖动 + 全屏偏移（任务 2）

- **手势**：岛窗口监听 `mousedown`（左键）且 `e.altKey` 为真 → 调 Tauri `start_dragging()` 让 OS 接管拖动；拖动过程中抑制悬停展开/收起的干扰。
- **落点持久化**：拖动结束（`mouseup`）读窗口新位置，相对当前「贴边基准」反算出 `offset_x/offset_y`，复用既有 `window_offset_apply`（clamp + 落盘 + 上屏）。借此天然支持「全屏任意位置」——不再局限于顶部居中。
- **与吸附的关系**：拖动落点若贴近某屏幕边缘（阈值在 T4 定稿），交给 T4 的吸附逻辑改 `dock_edge`；否则保留为自由偏移。
- **键**：拖动结果写入**当前模式**的 `window:offset_x/y:<mode>`（沿用按模式独立）。Alt 组合避免与单击展开/交互冲突。
- **勿动**：不新增全局热键；不改 `window_offset_apply` 现有契约，只新增前端手势与落点反算。

### T4 边缘自动吸附贴边（任务 1）

- **KV**：`window:dock_edge:<mode>` = `top`（默认）| `left` | `right` | `bottom`。缺键/非法回退 `top`（现状）。
- **后端定位泛化**：`top_center_position` 泛化为「贴边 + 居中 + gap」——按 `dock_edge` 计算基准点：top=顶边水平居中（现状）；bottom=底边水平居中；left=左边垂直居中；right=右边垂直居中。gap 沿用 `read_top_gap`（classisland 贴边=0）。`clamp_offsets` 同步泛化到四边。
- **几何角色互换**：贴左/右边时岛呈**竖条**，逻辑「宽↔高」互换（T1 的长度此时是竖条的纵向长度）。展开方向沿所在边向屏内（贴左边→向右展开）。涉及 `geometry_for` 输出朝向与前端布局朝向，是 T4 的主要工作量。
- **吸附检测**：T3 拖动落点距某边 < 阈值（物理像素，阈值在 T4 定稿）→ 写 `dock_edge` 并把 offset 归零重定位；从边缘拖走 > 阈值 → `dock_edge` 回 `top` 或保留为自由偏移（产品细节在 T4 定稿）。
- **设置**：`AppearancePanel` 加「停靠边」展示/手动切换（拖动吸附之外的手动入口）。

### T5 嵌入任务栏正式模式（任务 5）

> 状态：2026-08-17 原型观感经用户认可后立项正式实现（Goal 合同授权）；自动化已实现全绿，**待真机验收**。

- **模式契约**：`window:ui_mode` 正式值域 `island | classisland | taskbar`；前端 `parseUiMode` 与 Rust `normalize_ui_mode` 一致，缺键/非法值/历史 `corner` 回退 `island`。taskbar 外观只读写 `window:<property>:taskbar`（宽度 `window:width:taskbar`、透明度 `window:opacity:taskbar:expanded|compact`、偏移 `window:offset_x/y:taskbar`），不静默读取另两模式；全部随 portable 配置导入导出。
- **两窗口拆分**（13a 硬事实 1）：常驻嵌入条是独立 `taskbar-strip` WebView 窗口（140×≤任务栏高，透明无边框不抢焦点），经 Win32 `SetParent` 挂入 `Shell_TrayWnd` 开始按钮右侧；400px 展开面板继续用顶层 `island` 窗口，绝不放进任务栏父客户区。
- **定位与交互**：面板在任务栏上方左下角展开，左边缘对齐嵌入条左边缘（`taskbar_panel_rect`），底边距任务栏可见上沿 8px；点击嵌入条 toggle 展开/收起（`taskbar_strip_toggle_command` → `set_desired_state`），`Esc` 收起面板但 strip 保留；不做悬停展开与跨窗口失焦收起（13a 硬事实 2）。
- **模式切换事务**（`window_ui_mode_set`）：进入 taskbar 先收起 island 再 `enter_taskbar_mode`（SetParent + 样式 + `SetWindowPos` 定位，失败回滚 parent/style），成功后才落盘 KV；离开 taskbar 先 `leave_taskbar_mode`（解除父子、恢复样式、隐藏 strip）。任一步失败整体回滚到旧模式，不出现顶部岛与任务栏条双入口。
- **Win32 易错点**（13a 硬事实 3）：所有 Win32 调用集中在 `src-tauri/src/taskbar.rs`；`AttachThreadInput` 在 `Win32_System_Threading` feature；`SetWindowPos` 只改 z 序必须带 `SWP_NOMOVE|SWP_NOSIZE`。
- **恢复**：`start_runtime_watch` 每 2s 检查 `taskbar_needs_reattach`（strip HWND 失效 / 任务栏 HWND 或 Explorer PID 变化），命中即 `taskbar_reapply`（leave + enter）并广播 `window://taskbar-state-changed`；任务栏不可用时仅记日志、保留 taskbar 持久化，待下轮恢复。启动恢复：ui_mode=taskbar 先 `enter_taskbar_mode`，失败把 KV 回退 `island` 后走常规启动。
- **验收闸**：自动化全绿（前端 472 / Rust 159）后由你真机验收——条在开始按钮右侧、点击左下角展开复用面板、再点/Esc 收起、切回两旧模式无双入口、Explorer 重启后自动重挂、重启应用恢复、导入导出携带 taskbar 键。真机认可前不占进度表完成格。
- **明确不做**：不做组件配置化、不做悬停展开、不做跨窗口失焦自动收起、不改既有两模式行为。
