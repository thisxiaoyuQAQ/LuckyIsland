## 选定方案
- 方案：用户 2026-11-08 选择「1–9 全修」。
  - 1+6：新增拖动开始命令，Rust 在策略输入中标记拖动、清除悬停阶段，并把原生窗口改为 240×80 拖动几何（以光标为锚点）；落点结算先退出拖动态再按停靠边恢复几何与位置；结算失败的恢复路径同样退出拖动态。
  - 2：悬停阶段提交按快照 `desiredState` 分流，手动/通知展开（desired=expanded）时只同步阶段、不播收起动画，也不启动悬停周期。
  - 3：岛容器 `mouseenter` 只取消待决收起（不触发展开），右侧区语义不变。
  - 4+5：外层对齐按停靠边取向：bottom 贴底并把内边距放到屏内侧，right 用 `justify-end`。
  - 7：非贴边侧保留阴影余量，窗口几何不变。
  - 8：Windows 下 `resize_window` 用一次 `SetWindowPos` 同时设置位置与尺寸，其它平台保留两步调用。
  - 9：所有 `update_and_apply` 统一在主线程执行；非主线程调用经 `run_on_main_thread` 投递并等待结果，等待期间不持有策略锁。
- 改动范围：上表列出的前端文件与 `src-tauri/src/window_policy.rs`、`src-tauri/src/monitor.rs`、`src-tauri/src/lib.rs`（注册新命令与主线程标识）；不改 IslandState 值域，不改 taskbar 模式几何。
- 风险点：悬停/拖动/停靠组合多，需按矩阵回归；主线程投递若在主线程内重入会死锁，必须先判断当前线程；修改叠加在模块 14 未提交的真机反馈修复之上，真机验收与模块 14 同轮进行。

## 真机第 1 轮（2026-11-09）

- 现象：Alt+左键拖动后，原生窗口停在 240×80 拖动胶囊尺寸，里面却渲染展开态时间页（截图：大号时钟、日期、木鱼组件被裁切）；松手后不再吸附贴边。
- 根因（读 tao 0.35.3 源码确认）：
  - `start_dragging` 在 Windows 上只做 `ReleaseCapture` 并投递 `WM_NCLBUTTONDOWN` 就返回，前端的 `startDragging()` 在拖动开始前就 resolve。
  - tao 只在 `WM_EXITSIZEMOVE` 时给顶层窗口补发 `WM_LBUTTONUP`，网页收不到松手的 mouseup。
  - 因此前端只能靠 3 秒超时结算。拖动超过 3 秒，或结算提前触发时，结算发生在系统移动循环进行中：循环每次移动都按开始时的矩形（240×80）重设窗口，结算恢复的尺寸被冲掉，吸附也在错误时刻判定。
  - 08-18 版本也是 3 秒兜底，但那时拖动不改窗口尺寸，问题表现为不吸附；本 BUG 的 #6 让拖动胶囊成为真实窗口尺寸后才暴露成截图的样子。
- 修复：
  - 新增 `src-tauri/src/island_drag.rs`：`window_drag_begin` 改为 Rust 启动系统拖动，并起后台线程观测「主线程是否在系统移动循环（`GetGUIThreadInfo` 的 `GUI_INMOVESIZE`）」与「主按钮是否按下（`GetAsyncKeyState`，左右键互换时取右键）」。启动后 120ms 宽限，连续 2 次观测到已松开才投递主线程结算，然后广播 `window://drag-settled { id, ok, edge, error }`；观测上限 120 秒。
  - `DragRegistry` 保证每次拖动只被结算或取消一次，新拖动取代旧拖动。
  - `monitor::window_drag_drop_settle` 命令改为内部函数 `settle_drag`，前端不再调用。
  - 前端 `island-drag-controller.ts` 改为：进入拖动展示 → `windowDragBegin()` 拿 id → 收到同 id 的 drag-settled 才退出；130 秒兜底调用 `window_drag_cancel`；任务栏模式不进入拖动。
  - `Cargo.toml` 显式声明 windows 的 `Win32_UI_Input_KeyboardAndMouse` 特性（已被其它依赖启用，Cargo.lock 不变）。
- 测试：Rust `island_drag` 6 条（宽限、循环/按下等待、连续确认、120 秒上限、拖动登记唯一持有）；前端 `island-drag.test.ts` 控制器 12 条按新契约重写，`App.events.test.tsx` 新增 drag-settled 转发 1 条。均先 RED 后 GREEN。
- 复验：前端 53 files / 507 tests、Rust 185 passed / 1 ignored，fmt / clippy / check / build 通过。待用户第 2 轮真机验证。
