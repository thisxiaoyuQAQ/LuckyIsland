# 13a-左下角贴角模式

> 状态：🚧 13a.1 真机不达标（2026-07-26）→ 13a.2 已按修订契约实现，自动化全绿（typecheck、前端 437、四入口 build、Rust fmt/clippy、Rust lib 162 passed/1 ignored、cargo check），待真机验收；单人模式，main 分支线性
> 文档性质：模块 13（贴顶新 UI，`window:ui_mode` = island/classisland）之上的**增量契约**。基线不重复。
> 灵感来源：Windows 11 左下角天气/小组件那块——把灵动岛贴到屏幕左下角、平时最小、省屏幕空间。

## 模块做啥（1 行）

给 `window:ui_mode` 增加第三个值 `corner`：灵动岛贴到目标显示器**左下角、落在任务栏带内**（Win11 天气/小组件那块），平时最小胶囊/小条，悬停或点击才向上展开完整面板，最省屏幕空间（占任务栏而非内容区）。

## 依赖谁（1 行）

- 模块 13 已实现 `window:ui_mode`（island/classisland）、模式化定位 gap、`window_ui_mode_set`、`ui-mode.ts` store 与 `AppearancePanel` 开关——本增量复用同一套管线，只加 `corner` 分支。
- 执行门禁：遵循 `vault/CURRENT.md`；本文冻结契约优先。已按本契约实现（见文末「实现记录」）。

## 本轮范围

### 冻结设计（实现时照此落地）

1. **KV 值域**：`window:ui_mode` ∈ `island`(默认) | `classisland` | `corner`。`parseUiMode`（TS）与 `top_gap_for_mode`/ui_mode 读取（Rust）扩展第三值；缺键/空/非法一律回退 `island`（老用户无感）。
2. **定位（Rust `monitor.rs`）**：新增 `corner` 分支——锚点为目标显示器**整屏左下角**（含任务栏；`x = screen_left + margin`，`y = screen_bottom − current_height − margin`）；`offset_x`/`offset_y` 仍叠加、仍 clamp 到整屏内。island/classisland 维持顶部居中（gap 16/0）。
   - **关键实现考量（2026-07-26 用户反馈修正）**：用户要「落在任务栏里」而非任务栏之上——锚点用 `monitor.size` 的**整屏**底部（含任务栏），胶囊 alwaysOnTop 覆盖任务栏左端；**不**排除任务栏（早期误用工作区 `GetMonitorInfoW rcWork` 会让胶囊悬在任务栏上方，已废弃）。`y` 必须用**当前有效态（胶囊 80）高度**而非展开态（400），否则底边锚点抬高约 320px 悬空。
3. **展开方向（底部锚定）**：corner 是**底边锚定**——展开时窗口高度增大、`y` 上移以保持**底边不动**（面板向上生长）。这与 island/classisland 的顶边锚定（y 不动、向下生长）相反。`window_policy::resize_window` 现在「保顶部 y、只重算水平居中」；corner 需按模式改为「保底边 y、保左对齐」。
4. **形态（前端）**：corner 紧凑态 = 最小胶囊/小条（占角落一点点，最省地方）；四角圆角（悬浮在角落，非贴边直角）；悬停/点击复用 11a/13 的 hover/展开控制器展开完整面板（向上）。展开内容仍复用现有页面。
5. **切换**：`window_ui_mode_set` 接受 `corner`：写 KV → 按 corner 分支重新定位（左下角工作区）→ 广播 `settings://changed` → 前端换壳（锚点/圆角/展开方向）。随 07a 配置导出/导入（`window:` 前缀已在 `is_portable_setting` 白名单，无需改）。

### 明确不做（本轮 / 首版实现）

- 只做**左下角一个角**，不做右下/左上/右上四角可选（后续可扩）。
- 不做自由拖动定位（延续 F9.10「不提供自由拖动」的语义，避免与选屏/锚点冲突）。
- 不改窗口几何常量（`720×80`/`240×80`/`720×400` 不动）；corner 复用胶囊/紧凑/展开尺寸，只改**锚点边**与**展开方向**。
- 与 `floating_ball`/`hover_expand`/`click_through` 保持正交，不新增互斥逻辑。

## 已冻结产品决策

- 第三模式命名 `corner`（左下角）；三值互斥、单选下拉（`AppearancePanel` 界面模式）。
- 「省屏幕地方」= 紧凑态最小胶囊 + 贴角悬浮，非常显宽条。
- 贴角 = 整屏左下角、落在任务栏带内（含任务栏，alwaysOnTop 覆盖任务栏左端），默认 `offset 0/0` + 小 margin(12px)；偏移仍可微调。
- 展开向上（底边锚定），底边留在任务栏处、面板向上生长。

# 13a.2 修订契约：真嵌入任务栏 + 三模式独立外观（2026-07-26）

> 本节取代 13a.1 中「corner 单窗口贴整屏左下角」的定位与形态设计；13a.1 的 `window:ui_mode` 三值、模式化定位管线、AppearancePanel 三选一继续有效。

## 为什么推翻 13a.1

用户真机反馈「没到最左下角、还是悬浮在任务栏上而不是嵌入任务栏」。只读定位结论：

1. `window_policy.rs` corner 静息态复用 `Capsule` 几何 **240×80 逻辑像素**，而 Win11 任务栏仅约 **48 逻辑像素**高。底边贴屏底后窗口顶边必然高出任务栏 30~45px 溢出到内容区 → 观感即「盖在任务栏上的悬浮卡片」。
2. `CORNER_MARGIN_PHYSICAL = 12` 让 x/y 各离屏角 12px → 「没到最左下角」。
3. 全程无任务栏矩形探测（`full_rect()` 只取整屏），高度无法对齐任务栏带。
4. `App.tsx` corner 外壳仍是 `rounded-2xl + border + shadow-2xl`，强化悬浮观感。

同轮暴露的第二个问题：`window:opacity` / `window:offset_x` / `window:offset_y` 是**全局单键**，三种界面模式共用一份值——为 corner 调的偏移会破坏 island 的位置。

## 已冻结产品决策（2026-07-26 交互式确认）

| 决策项 | 结论 |
|---|---|
| 嵌入方式 | **真嵌入**：Win32 `SetParent` 到 `Shell_TrayWnd`，成为任务栏子窗口 |
| 展开态架构 | **双窗口**：常驻嵌入条（新窗口）+ 展开面板（复用现有 island 窗口） |
| 静息条形态 | 宽约 200 逻辑像素、高 = 探测到的任务栏高度；内容 = 时间 + 天气温度 |
| 外观键存储 | 后缀键 `window:<项>:<mode>`；旧全局值一次性迁移给 `island`，另两模式用默认 |
| 设置面板呈现 | 滑块跟随当前界面模式，切模式即切值 |

**硬约束（决定架构的 Win32 事实）**：`WS_CHILD` 子窗口被父窗口客户区裁剪。嵌进 48px 高的任务栏后，720×400 的展开面板会被裁成 48px。因此展开态**必须**是另一个不嵌入的顶层窗口，不能靠同一个窗口向上生长。

## 窗口分工

| 窗口 | label | 归属 | 职责 |
|---|---|---|---|
| 嵌入条 | `taskbar-strip` | `Shell_TrayWnd` 子窗口（`corner.html`） | corner 模式常驻静息 UI：时间 + 天气温度；悬停/点击驱动展开 |
| 展开面板 | `island` | 顶层置顶窗口（现有 `index.html`） | corner 模式下平时隐藏；悬停/点击才显示在**任务栏正上方**（工作区左下角，底边锚定） |

corner 模式下 island 窗口的锚点回到**工作区**底边（`rcWork.bottom` = 任务栏顶），不再压任务栏——任务栏那一格已经由嵌入条占据。13a.1「锚整屏底部」的决定随本节作废。

## 定位契约（Rust）

- `taskbar.rs`（新增，Windows 专属）
  - `taskbar_rect(monitor) -> Option<ScreenRect>`：主屏取 `Shell_TrayWnd`，副屏遍历 `Shell_SecondaryTrayWnd` 取与目标显示器相交者；`GetWindowRect` 物理像素。
  - `embed(hwnd, tray)`：`GWL_STYLE` 去 `WS_POPUP` 加 `WS_CHILD` → `SetParent` → `SetWindowPos(SWP_NOACTIVATE)` → `AttachThreadInput` 打通输入。
  - `detach(hwnd)`：`SetParent(NULL)` + 还原 `WS_POPUP` + 重新置顶，供切出 corner 模式使用。
  - `strip_rect_in_taskbar(taskbar, width, height, offset_x, offset_y)`：纯函数，返回相对任务栏客户区的 (x, y)，clamp 在任务栏矩形内，可单测。
- **嵌入失败必须降级不崩**：找不到 `Shell_TrayWnd` 或 `SetParent` 失败时，嵌入条保持为顶层置顶窗口，按同一矩形覆盖在任务栏左端（观感退回 13a.1 的「贴」而非「嵌」），并 `tracing::warn`。任何情况下不得出现「窗口消失且无静息 UI」。
- **看门狗**：复用 `start_runtime_watch` 的 2 秒轮询；corner 模式下检查 `GetParent(strip) == tray && IsWindow(tray)`，不成立则重新探测并重挂（覆盖 explorer 重启、任务栏位置/高度变化、DPI 变化）。

## 窗口策略契约（`window_policy.rs`）

corner 语义从「静息=胶囊」改为「静息=嵌入条，island 隐藏」：

| 输入 | island 有效态 | 嵌入条 |
|---|---|---|
| `desired = Hidden`（Alt+X 隐藏） | Hidden | 隐藏 |
| `hide_in_fullscreen && fullscreen_block` | Hidden | 隐藏 |
| corner + `desired = Compact` + `hover_stage = 0` | **Hidden** | 显示 |
| corner + `desired = Compact` + `hover_stage = 1` | Compact（720×80） | 显示 |
| corner + `desired = Compact` + `hover_stage ≥ 2` + `hover_expand` | Expanded（720×400） | 显示 |
| corner + `desired = Expanded`（点击嵌入条） | Expanded | 显示 |

`floating_ball` 的胶囊投影语义不变，corner 不再复用它。非 corner 模式的全部行为逐字不变。

## 外观键契约（三模式独立）

```text
window:opacity:<mode>    mode ∈ island | classisland | corner   默认 0.7
window:offset_x:<mode>   默认 0
window:offset_y:<mode>   默认 0
```

- **一次性迁移**（启动时幂等）：若 `window:opacity:island` 不存在且旧 `window:opacity` 存在 → 复制；`offset_x`/`offset_y` 同理。旧全局键保留只读兜底，不再写入。
- 读取顺序：先读 `window:ui_mode` → 再读该模式的后缀键 → 缺键回默认。
- `window_offset_apply` 写当前模式的后缀键；`resetAppearance` 只重置当前模式。
- 导入导出：后缀键仍以 `window:` 开头，命中既有 `is_portable_setting` 白名单，无需改白名单；`config_import` 的 `needs_offset_apply` 判定改为按 `window:offset_` **前缀**匹配。
- 前端 `AppearancePanel` 三个滑块绑定「当前界面模式」，切模式时重新读取该模式的值，并在标题旁标明作用模式。

## 静息条内容契约

- 布局：单行，左时间（`HH:mm`，tabular-nums）+ 右天气温度（`weather_get_city` → `weather_get`，10 分钟刷新，失败或未配置城市时降级显示日期 `MM/DD`）。
- 背景：`color-mix(in oklch, var(--card) <corner 透明度>%, transparent)`，跟随主题；无圆角、无边框、无阴影（贴合任务栏）。
- 交互：`mouseenter` → `window_hover_stage_set(1)`；持续悬停由现有 `createHoverStageController` 升到 2；`click` → `set_island_state("expanded")`；`mouseleave` 交还既有 leave 逻辑。

- 不改 island 窗口的 `720×80 / 720×400` 几何常量。
- 不为嵌入条做独立的页面切换/滚轮/多页内容（它只是入口）。
- 不改 island/classisland 两模式的任何定位、形态与动画行为。

## 实现记录（13a.2，2026-07-26）

按上文冻结契约落地，与契约的差异都在本节写明：

- **新增 `src-tauri/src/taskbar.rs`**：纯函数（`strip_offset_in_taskbar` / `strip_screen_position` / `pick_taskbar_for_monitor` / `fallback_taskbar_rect`）+ Windows 平台层（`taskbar_rects` / `taskbar_hwnd_for` / `embed` / `detach` / `is_child_of` / `move_child`）+ 生命周期（`sync_strip` / `resync_strip` / `watchdog` / `place_strip`）。嵌入路径：`GWL_STYLE` 去 `WS_POPUP` 加 `WS_CHILD` → `SetParent` → `SetWindowPos(SWP_NOACTIVATE|SWP_NOZORDER)` → `AttachThreadInput`（`Win32_System_Threading`，不是 `KeyboardAndMouse`）。
- **只认底部停靠的任务栏**（`bottom_docked_taskbar`）：左/右/上侧停靠时不尝试嵌入，退化为屏底兜底带的覆盖定位。
- **嵌入条改为运行时按需创建**（与契约中「静态声明」不同）：非 corner 模式下直接 `destroy()`，避免为 island/classisland 用户常驻一个 WebView2 实例（几十 MB）；corner 模式内的 Alt+X / 全屏隐藏只 `hide()` 不销毁，避免重建延迟。新增 `src-tauri/capabilities/taskbar-strip.json`（`core:default`）。
- **新增命令 `window_strip_hover_release`**（契约未预见）：两个窗口不共享 DOM 的 enter/leave，指针从条移到面板的半路上没有任何 enter 事件。条在 `mouseleave` 后延迟 360ms 调用它，后端用 `cursor_position()` 判断指针是否已落在 island 面板矩形内——是就不清 hover 阶段，交给面板自己的 leave 收起。
- **`window_policy.rs`**：`reduce` 中 corner + Compact 意图 → `Hidden`（静息 UI 是嵌入条），优先级在 floating_ball 的胶囊投影之前；新增 `strip_visible(inputs)`；`update_and_apply` 成为条与岛的同一个裁决点，条同步失败只 `warn` 不回滚岛。
- **`monitor.rs`**：`CORNER_MARGIN_PHYSICAL` 12 → 0（贴死最左下角）；新增 `corner_bottom_anchor`（任务栏顶边，探测不到退屏底）与 `PlacementGeometry`（`place_island` 参数收敛，满足 clippy 7 参数上限）；新增 `normalize_ui_mode` / `current_ui_mode` / `mode_key` / `migrate_appearance_keys` / `resolved_monitor_target` / `current_offsets`；`read_offsets` 与 `window_offset_apply` 全部改读写模式后缀键。
- **`settings_window.rs`**：`needs_offset_apply` 由等值判断改为 `window:offset_` 前缀判断（覆盖模式后缀键）。
- **前端**：新增 `corner.html` + `src/corner/{main,TaskbarStrip}.tsx`（时间 + 天气温度，失败降级日期；`data-opacity` 便于断言与排查）；`vite.config.ts` 加第四入口；`settings.ts` 加 `modeKey` / `UI_MODES` / `UI_MODE_LABELS`；`useIslandSettings` 在 ui_mode 应用之后再读该模式的透明度，并在模式变更时重读；`AppearancePanel` 三个滑块按当前模式读写、切模式即切值、重置只重置当前模式；`App.tsx` corner 外壳改为「只上圆角、无底边」。
- **迁移**：`lib.rs` 启动时在恢复窗口位置之前调用 `migrate_appearance_keys`（幂等：目标键已存在或旧键不存在都跳过）。

### 已知风险（需真机确认）

1. `WS_CHILD` + `transparent: true` 的 WebView2 子窗口在部分环境可能渲染异常（黑底/不透明）。若真机出现，最小修复是把嵌入条窗口改为不透明并用主题色贴近任务栏底色。
2. 跨进程 `AttachThreadInput` 后仍收不到 hover/click 的话，交互要退化为「只能点击」或改用 Win32 消息钩子。
3. explorer 重启由 2 秒看门狗兜底，重挂之前最多有 2 秒错位/消失。
